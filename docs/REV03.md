# REV.03 - Native Blender render and handover record

Contest #2801401 - Luxury Crystal & Perfume Boutique (~99 sqm).

The six interior/proof images are rendered directly by Blender 5.1.1 (build b70da489d7f4), using native meshes, Cycles lighting, procedural materials and Freestyle. No AI image generator, generative image editing, image-based scene backdrop or painted-over rendering is used. The parametric scene and build pipeline were prepared with coding assistance; this is not a claim of manual-only authorship.

## Paint and light

Walls, structural columns COL-01 through COL-04 and ceiling use BM OC-17 White Dove `#F3EFE6`. Painted niches and selected fixture bodies use BM OC-85 Pale Oak `#E6DEC8`. Both paint shaders have roughness 0.85. These are the requested digital colour targets; physical paint samples are required before procurement.

No stone, travertine, wood veneer or heavy wall panels are specified. Small metal/glass display frames remain distinct from wall finishes. Wood is limited to product gift boxes and freestanding office furniture. Broad neutral area lights, ceiling bounce, soft daylight and restrained highlight exposure produce the bright views. The exposure setting is calibrated against the actual added light energy rather than used as a brightness claim.

## Exact-camera evidence

Each colour/proof pair is rendered consecutively from the same scene. Only shading and Freestyle edge display change. The camera world matrix, focal length, sensor width, shifts, clip distances, pixel aspect, render dimensions, object visibility and evaluated vertices/faces remain unchanged. Glass remains transparent in the proof so the enclosed products can still be inspected.

`exports/render_manifest.json` records both captures, SHA-256 image hashes, evaluated mesh hashes, native `.blend` hash, script hashes, Blender version/build and architecture material audit. The board compositor checks these hashes before it accepts a render. An overwritten image therefore fails composition until it is regenerated by Blender.

VIEW 04 is a separate wall-section presentation, not a same-camera overlay. Walls are temporarily cut at 850 mm; the downloadable perspective `.blend` retains uncut source geometry. No source mesh is replaced with a photographed or generated interior.

## Client references and drawing scope

The product reference strip uses the client's supplied files. Three source filenames contain `Gemini_Generated_Image`; their original marks are retained and every reference is labelled separately from the native design renders. They are not evidence of the origin of the proposed interior. They are never used as textures or backdrops in the Blender scene.

99.27 sqm is the source-plan label. The dimension-derived L-shaped CAD boundary measures 113.21235 sqm including the 14.78130 sqm existing service core; the remainder is 98.43105 sqm. Coordinates are not scaled to force agreement.

The detailed perspective model and CAD-coordinate axonometric model are distinct existing model branches. The perspective scene includes a curved sofa/counter, recessed display niches and a 3200 mm ceiling; the CAD reference retains its 2800 mm ceiling and dimensioned fit-out layout. Structural column plan footprints in the perspective scene now read directly from the same CAD geometry JSON. The same-camera claim applies to the perspective image/proof pairs, not to full fit-out equivalence between these two model branches. Site dimensions, final fit-out coordination and acoustic/security performance are not certified by these renders.

The DWG is a native R2000 binary produced by LibreDWG and checked by DXF round-trip. Its annotations are vector outlines. The companion R2010 DXF retains editable text and dimensions. Autodesk AutoCAD application verification has not been performed.

## Rebuild

Run from the project root using the existing installed tools; no dependency installation is required.

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup --python scripts/render_blender.py
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup --python scripts/render_cad_axonometric.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/verify.py
PYTHONDONTWRITEBYTECODE=1 /usr/local/bin/python3.11 scripts/compose_boards.py
```

`build_blender_boutique.py` builds the detailed scene; `render_blender.py` orchestrates the six required views and provenance. For quick review, prefix the render command with `BOUTIQUE_PREVIEW=1`. Preview images, the preview `.blend` and preview manifest go to `review/preview_renders/` and never replace final assets. In preview mode only, set `BOUTIQUE_VIEWS=1,2,3,4` to choose views. Final delivery renders all four views and both paired proofs together; partial final runs are rejected before they can overwrite the native model or manifest.

For CAD material/dimension revisions, update `scripts/geometry.py`, then run `scripts/geometry.py`, `scripts/build_cad.py`, `scripts/convert_dwg.py`, the CAD Blender renderer and `scripts/verify.py` in that order. Rebuild the boards last.

## Verification

After a full rebuild, reopen the native model and check the delivery bytes:

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b exports/Crystal_Perfume_Boutique_99sqm.blend --python-exit-code 1 --python scripts/verify_blender_rev03.py
PYTHONDONTWRITEBYTECODE=1 /usr/local/bin/python3.11 scripts/verify_rev03.py
```

Local review records are in `review/board_audit_rev03.json`, `review/rev03_delivery_validation.json`, `review/rev03_web_smoke.json` and `review/rev03_preview_safety.json`. The safety check compares the final native model, manifest and all six image hashes before/after a selected-view preview, then confirms that a partial final run is rejected without altering those files. Delivery verification checks dimensions, camera pairs, source hashes, PDF page sizes, every packaged file and the local `docs/` mirror. Browser checks cover both local web routes at desktop/mobile widths, four tabs, zoom/fit, eight links per route and page-script errors.
